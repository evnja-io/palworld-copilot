# Phase 5.5 — Import automatique (cron) + pseudos in-game : Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> USER ACTIONS : activer l'API REST chez l'hébergeur, fournir les coordonnées
> SFTP/FTP et poser les secrets GitHub. Exécution inline recommandée (petite
> phase, itérations avec l'utilisateur).

**Goal:** Toutes les 6 h, un workflow GitHub Actions télécharge les `Players/*.sav` du serveur hébergé (SFTP/FTP), les importe (CLI existant), et associe chaque GUID à son **pseudo in-game** (API REST du serveur) pour que la page `/import` affiche « Sephi74 » plutôt qu'un GUID hexadécimal.

**Architecture:** Nouvelle table `save_players (player_guid pk, nickname, updated_at)` alimentée par un script `fetch-players.ts` (GET `/v1/api/players`, auth Basic admin) — le mapping se complète au fil des polls (seuls les joueurs connectés apparaissent) et persiste. La page `/import` joint le pseudo au listing. Un workflow `.github/workflows/import-saves.yml` (cron 6 h + déclenchement manuel) reconstruit le venv palsav sur le runner, télécharge les saves via `lftp`, lance `import-save` puis `fetch-players`. Secrets GitHub pour tout ce qui est sensible.

**Tech Stack:** existant + `lftp` (runner uniquement) ; aucune dépendance npm nouvelle.

## Global Constraints

- Invariants d'import inchangés : additif strict vers `progress`, remplacement limité à `save_snapshots` du GUID, IDs canoniques
- Secrets JAMAIS en clair dans le repo : `DATABASE_URL`, `SAVE_FTP_*` (host/port/user/pass/chemin/protocole), `PAL_API_URL`, `PAL_API_PASSWORD` — secrets GitHub Actions
- `save_players` : upsert par GUID (le dernier pseudo vu gagne), jamais de suppression
- Correspondance GUID : le `playerId`/`playeruid` de l'API doit être normalisé au format des noms de fichiers de saves (32 hex majuscules sans tirets) — format exact à CONSTATER au spike (Task 1), ne pas supposer
- `/import` : pseudo affiché si connu, sinon GUID abrégé comme aujourd'hui ; i18n FR/EN
- Le workflow doit échouer visiblement (exit code) si le téléchargement OU l'import échoue, mais un échec de `fetch-players` (serveur éteint) ne doit PAS faire échouer l'import des saves
- Branche : `feature/phase-5.5-cron-import`

### Task 4: Workflow GitHub Actions + secrets (USER ACTION)

**Files:**
- Create: `.github/workflows/import-saves.yml`
- Modify: `docs/extraction-runbook.md` (section cron : secrets, déclenchement manuel, lecture des logs)

**Interfaces:**
- Consumes: secrets GitHub (`DATABASE_URL`, `SAVE_FTP_HOST`, `SAVE_FTP_PORT`,
  `SAVE_FTP_USER`, `SAVE_FTP_PASS`, `SAVE_FTP_PATH`, `SAVE_FTP_PROTOCOL`
  (`ftp`|`sftp`), `PAL_API_URL`, `PAL_API_PASSWORD`)
- Produces: workflow `import-saves` : cron `0 */6 * * *` + `workflow_dispatch`

- [ ] **Step 1: Écrire le workflow**

`.github/workflows/import-saves.yml` :
```yaml
name: import-saves
on:
  schedule:
    - cron: "0 */6 * * *"
  workflow_dispatch:
concurrency: import-saves
jobs:
  import:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm }
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - name: Dépendances node (pipeline seul)
        run: pnpm install --filter @palworld-companion/pipeline
      - name: venv palsav + palooz
        run: |
          cd packages/pipeline
          python3 -m venv .venv
          git clone --depth 1 https://github.com/deafdudecomputers/PalworldSaveTools /tmp/pst
          .venv/bin/pip -q install /tmp/pst/src/palsav/palooz /tmp/pst/src/palsav
      - name: Télécharger les saves (lftp)
        env:
          H: ${{ secrets.SAVE_FTP_HOST }}
          P: ${{ secrets.SAVE_FTP_PORT }}
          U: ${{ secrets.SAVE_FTP_USER }}
          PW: ${{ secrets.SAVE_FTP_PASS }}
          DIR: ${{ secrets.SAVE_FTP_PATH }}
          PROTO: ${{ secrets.SAVE_FTP_PROTOCOL }}
        run: |
          sudo apt-get -yq install lftp > /dev/null
          mkdir -p /tmp/saves
          lftp -e "set sftp:auto-confirm yes; open -u \"$U\",\"$PW\" -p \"$P\" \"$PROTO://$H\"; mget -O /tmp/saves \"$DIR\"/*.sav; bye"
          ls -la /tmp/saves
      - name: Import
        env: { DATABASE_URL: "${{ secrets.DATABASE_URL }}" }
        run: cd packages/pipeline && node --experimental-strip-types src/import-save.ts /tmp/saves
      - name: Pseudos (API REST — non bloquant)
        continue-on-error: true
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
          PAL_API_URL: ${{ secrets.PAL_API_URL }}
          PAL_API_PASSWORD: ${{ secrets.PAL_API_PASSWORD }}
        run: cd packages/pipeline && node --experimental-strip-types src/fetch-players.ts
```
Note : `import-save.ts` lit actuellement l'env via `--env-file` dans le script
pnpm — vérifier qu'appelé ainsi (env process direct) il fonctionne ; sinon
ajuster l'appel. Adapter si le script prend le dossier en argument (oui).
